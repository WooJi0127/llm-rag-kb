# 物联网与嵌入式知识库（示例语料）

本文件是 llm-rag-kb 的示例语料，覆盖物联网、嵌入式、MQTT、STM32、大模型等主题。你可以把自己的笔记、产品文档放到 data/ 目录，系统会自动索引。

## 物联网基础

物联网（IoT）是指通过信息传感设备，按约定的协议把任何物品与网络连接起来，进行信息交换和通信，以实现智能化识别、定位、跟踪、监控和管理的一种网络。典型的物联网架构分为感知层、网络层和应用层三层。

感知层负责采集物理世界的数据，常用设备包括温湿度传感器、光照传感器、加速度计等。网络层负责数据传输，常见协议有 MQTT、CoAP、HTTP、LoRaWAN 等。应用层负责数据的存储、分析与呈现。

## MQTT 协议

MQTT 是一种基于发布/订阅模式的轻量级消息传输协议，专为受限设备和低带宽、高延迟网络设计。它包含三个角色：发布者、订阅者和代理（Broker）。设备把数据发布到某个主题（Topic），订阅同一主题的应用即可收到消息。MQTT 支持三种服务质量等级 QoS0、QoS1、QoS2，分别保证最多一次、至少一次和恰好一次送达。

在物联网项目中，传感器节点通常通过 ESP8266/ESP32 等 WiFi 模组，使用 AT 指令连接 MQTT Broker，把采集到的温湿度数据发布到如 iot/sensor 这样的主题上，云端或边缘服务订阅该主题即可实时获取。

## STM32 与嵌入式开发

STM32 是意法半导体推出的基于 ARM Cortex-M 内核的 32 位微控制器系列，广泛用于嵌入式与物联网终端。常见的开发方式包括使用 STM32CubeMX 生成初始化代码，配合 HAL 库和 FreeRTOS 实时操作系统。

在传感器终端中，STM32 通常负责周期性读取温湿度（如 DHT22、AHT20）、光照（如 BH1750）等传感器数据，并通过 UART 或 WiFi 模组上报。FreeRTOS 可以把"采集""上传""看门狗"等拆成独立任务，提高系统可靠性。

## 边缘计算与异常检测

边缘计算是指在靠近数据源的网络边缘侧进行数据处理，而不是全部上云。它的好处是降低时延、减少带宽占用、保护数据隐私。在环境监测场景中，可以在边缘侧对传感器流做异常检测，例如基于滑动窗口的 Z-score 方法：计算近期读数的均值与标准差，当某次读数偏离均值超过若干倍标准差时判定为异常。检测到异常后再决定是否上送云端，从而大幅减少无效数据传输。

## 大模型与 RAG

大模型（LLM）是指参数规模巨大的自然语言模型，能够理解并生成文本。RAG（检索增强生成，Retrieval-Augmented Generation）是一种让大模型基于私有知识作答的技术：先根据用户问题从知识库检索相关段落，再把这些段落作为上下文送给大模型生成答案，从而缓解"幻觉"问题。

本地部署大模型常用 Ollama、vLLM 等工具。Ollama 可以在个人电脑或服务器上拉取并运行 Qwen、Llama 等开源模型，通过本地 HTTP 接口供应用调用，既保护隐私又无需联网费用。结合向量数据库（如 Chroma）或轻量级 BM25 检索，就能搭建一套完全本地化的知识库问答系统。

## 本地模型部署

本地部署大模型的关键考量包括显存/内存占用、推理速度与并发能力。量化（如 4-bit、8-bit）可以显著降低资源占用。对于没有 GPU 的环境，可以选择参数较小的模型（如 1.5B 级别）并配合量化，在 CPU 上也能获得可用的响应速度。部署后通常通过 OpenAI 兼容接口或 Ollama 的原生接口对外提供服务。
