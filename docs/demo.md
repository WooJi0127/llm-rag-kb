# 60–90 秒演示

先设置 USE_LLM=0，并运行 python run.py。命令入口自动使用 UTF-8 输出。演示前执行测试命令，避免现场下载依赖或模型。

1. 0–15 秒：说明项目帮用户在自己的文字笔记中找证据；只需 Python 标准库。打开 localhost:8002。
2. 15–35 秒：点击 MQTT，展示回答后的块 ID，展开证据原文。指出当前实际模式是 demo；摘录来自本地文本，不是模型自由作答。
3. 35–50 秒：输入 xyzzynonexistent，看到“资料不足”。再解释 STM32 warranty price 虽然可能命中 STM32 资料，却不能保证回答保修价格，人工核对仍必要。
4. 50–70 秒：展示 python -m unittest discover -s tests -v 的 OK 与评测输出。说明独立 5 文档、11 查询，小数据上的检索指标不等于答案正确率。
5. 70–90 秒：说明模型是可选增强；失败、空输出、繁忙会显示实际 demo 模式和原因。打开代码中固定窗口与缓存词频实现，讲清一项取舍。

## 面试问题与回答线索

- 为什么选择 BM25？零必需依赖、结果便于解释；不足是语义改写和中文单字歧义。下一步应先补真实标注查询，再比较可选语义检索。
- 为什么不按标点强制分块？固定字符窗口能保证长无标点文本的上限与精确重叠；代价是句子可能被切断。
- topk 是块还是文档？线上 search 返回块；离线评测去重后按文档计算，标签不随分块改变。
- Recall 和 MRR 有何差别？前者衡量相关集合覆盖，后者关注首个相关结果位置；都不衡量答案事实正确性。
- 模型异常会怎样？有界并发、网络操作超时、失败回退，返回实际 mode/fallback_reason；HTTP health 独立响应。没有严格总耗时保证。
- 有来源就可信吗？来源仅让人核查；低分词面命中、资料过时和模型误引仍可能出现。模型 evidence 是提示上下文，不是自动事实证明。
- 如何避免测试只测实现？长文测试重建原文并检查真实重叠；HTTP 测试通过本地套接字发送坏请求；指标测试用手算排名验证去重与分母。模型使用替身，明确覆盖范围。
